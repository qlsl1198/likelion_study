## 슬라이드: useEffect, 쉽게 말하면?

**멘트**

> "**useEffect**를 쉽게 말하면, **『화면 그리기(렌더링)가 끝난 뒤에 해야 할 일』**을 정하는 자리예요."

> "React는 **UI를 그리는 것**과 **그 밖의 일**을 분리하려는 성격이 강해요. 예를 들어 **서버에서 데이터 받아오기**, **타이머 돌리기**, **웹소켓 구독하기** 같은 건 **그리기 자체**는 아니죠. 그런 걸 **사이드 이펙트**라고 부르고, **useEffect** 안에 두는 패턴이 일반적이에요."

> "**의존성 배열**만 기억해도 오늘의 절반은 갑니다.  
> **`[]`** — 처음 붙을 때 한 번만 실행하고 싶을 때가 대표적이에요.  
> **`[값]`** — 그 값이 바뀔 때마다 다시 실행.  
> **배열 없음** — 렌더링이 될 때마다 거의 실행돼요. **실수로 배열을 빼먹는 경우**가 많아서, 수업에서는 **일부러 비우지 않는 이상 배열을 항상 쓰는 습관**을 권해요."

> "**Props drilling**은, 부모에서 준 데이터를 **안 쓰는 중간 컴포넌트들을 거쳐** 계속 아래로만 넘겨야 하는 상황을 말해요. 오늘 배울 **Context**가 그 불편을 줄이는 도구 중 하나예요."

**비전공자 팁**

- "마운트" = 컴포넌트가 **처음 DOM에 붙는 순간**. "언마운트" = **사라질 때**.

## 슬라이드: 1.1 Hooks란?

**멘트**

> "**Hooks**는 **함수형 컴포넌트** 안에서만 쓰는, 이름이 `use`로 시작하는 **특별한 함수들**이에요. 대표적으로 지난주 배운 **useState**, 오늘의 **useEffect**, **useContext** 등이 있어요."

> "**규칙**이 세 가지로 정리돼 있어요.  
> 첫째, **최상위에서만 호출**한다.  
> 둘째, **조건문·반복문·중첩 함수 안에서 호출하지 않는다.**  
> 셋째, **React 함수 컴포넌트 또는 커스텀 Hook** 안에서만 호출한다."

> "**왜** 조건 안에 넣으면 안 되냐면, React는 Hook을 호출한 **순서**로 내부 상태를 매칭해요. 렌더마다 **호출 순서가 달라지면** 엇박이 나서 버그가 나요. 그래서 **항상 같은 순서**로만 Hook이 불리게** 규칙이 생긴 거예요."

**질문 대비**

- "클래스 컴포넌트는요?" → "예전 방식이고, 지금은 **함수형 + Hooks**가 표준이에요."

**전환**

> "어떤 Hook들이 있는지 **주요 Hooks** 슬라이드로 훑어볼게요."

## 슬라이드: 1.2 주요 Hooks

**멘트**

> "**useState** — State, 지난주 했죠.  
> **useEffect** — 렌더 이후 부가 작업, 오늘의 주인공.  
> **useContext** — Context 값 읽기.  
> **useRef** — DOM 가리키거나, 렌더에 영향 없이 값 저장.  
> **useMemo** — 계산 결과 **메모**해서 비용 줄이기.  
> **useCallback** — 함수 참조 **메모**해서 자식에게 넘길 때 리렌더 줄이기."

> "오늘 수업에서는 **useEffect**와 **useContext**에 비중을 두고, **useMemo·useCallback**은 이름만 알아 두시면 됩니다. **최적화** 주차에서 다시 다룰 수 있어요."

**전환**

> "**2부, useEffect**로 넘어갑니다. 시간을 가장 많이 쓸 파트예요."

## 슬라이드: 2.1 useEffect란?

**멘트**

> "**정의** 다시 한 번: 컴포넌트가 **렌더링된 뒤**에 실행되는 Hook이에요."

> "**용도**: 서버에서 데이터 가져오기, 이벤트 구독, 타이머, DOM 측정 같은 **렌더 결과에 의존하는 작업**이나 **렌더와 분리하고 싶은 작업**을 넣어요."

> "**의존성 배열** 세 가지를 외우세요.  
> **없음** — 거의 매 렌더마다 effect가 돌아가요. 특수한 경우가 아니면 **비추천**.  
> **`[]`** — **마운트 직후 한 번**이 대표적이에요. API 한 번 받아오기 등.  
> **`[a, b]`** — **a 또는 b가 이전 렌더와 달라졌을 때** effect를 다시 실행해요."

> "퀴즈 정답과 연결하면, **`[]`** 는 **처음 붙을 때 한 번** 실행되는 패턴이에요. effect 안에서 **return 함수**를 주면, 그건 **클린업**이고 **언마운트 전**에 호출돼요."

**전환**

> "코드 형태를 **기본 사용법** 슬라이드에서 보겠습니다."

---

## 슬라이드: 2.2 기본 사용법

**멘트 (코드 따라가기)**

> "`import { useEffect } from 'react'` — React에서 가져옵니다."

> "`useEffect(() => { ... }, [deps])` — 첫 인자는 **함수**, 두 번째가 **의존성 배열**이에요. 슬라이드 예제는 배열이 생략된 형태로, **마운트·업데이트마다** 로그가 찍히는 쪽에 가깝습니다."

> "`return () => { ... }` — **클린업 함수**예요. 다음 effect 실행 전이나 **컴포넌트가 사라지기 전**에 호출돼요."

**데모 제안**

> "같은 코드를 프로젝트에 넣고, 저장할 때마다 콘솔이 어떻게 찍히는지 보여 주세요."

**전환**

> "의존성 배열을 **텍스트로만** 한 번 더 정리하고, **예제 코드**로 이어갈게요."

## 슬라이드: 2.4 데이터 가져오기

**멘트**

> "`UserProfile`이 **`userId`** 를 props로 받는다고 해 볼게요. **user**와 **loading**을 state로 두었죠."

> "`useEffect` 안에서 `async function fetchUser`를 정의하고 호출해요. **`userId`가 바뀔 때마다** 다시 가져오려고 의존성 배열에 **`[userId]`** 를 둔 거예요."

> "**로딩 중**이면 스피너나 `'Loading...'`** 을 보여 주고**, 데이터가 오면 **이름**을 보여 줘요."

> "**주의**: `useEffect`의 첫 인자 함수 자체를 **`async`로 만들지 않는** 팀도 많아요. 대신 안에서 async 함수를 정의하고 호출하는 슬라이드 패턴이 안전해요. (Promise를 직접 반환하는 것과의 미묘한 차이 — 입문에서는 **지금 패턴**만 따라와도 됩니다.)"

## 슬라이드: 3.1 Context API란?

**멘트**

> "**정의**: Props drilling을 줄이기 위한 **전역에 가까운** 데이터 공유 방법이에요."

> "**Props drilling**을 다시 말하면, App → Layout → Sidebar → Menu처럼 **Menu만 필요한데** 중간이 다 전달자 역할을 하는 거예요."

> "**Context**는 **Provider**로 트리 한 덩어리를 감싸면, 그 안의 어떤 깊이에서든 **useContext**로 같은 값을 읽을 수 있어요."

> "**남용 주의**: 뭐든 Context에 넣으면 **데이터가 어디서 왔는지** 추적이 어려워져요. **테마, 로그인 사용자, 언어 설정**처럼 **진짜 넓게 쓰는 것**에 쓰는 게 좋아요."

**전환**

> "코드로 **생성·사용**을 보겠습니다."

## 슬라이드: 3.2 Context 생성 및 사용

**멘트**

> "`createContext('light')` — 기본값은 **Provider 밖**에서 읽을 때 쓰는 fallback이에요."

> "`ThemeContext.Provider value={{ theme, setTheme }}` — **객체로** state와 setter를 같이 내려보낸 거예요."

> "`Header`에서 `useContext(ThemeContext)`로 꺼내 쓰고, 버튼으로 **테마 토글**을 할 수 있어요."

> "**주의**: Context 값이 바뀌면 **Provider 아래 전체가 리렌더**될 수 있어요. 값을 **자주 바꾸는 무거운 데이터**는 나중에 **상태 관리 라이브러리**를 검토한다고만 말해 둘게요."

## 슬라이드: 4.3 Link와 NavLink

**멘트**

> "**`Link to="/"`** — 클릭하면 URL이 바뀌고, **전체 새로고침 없이** 해당 Route 화면으로 바뀌어요."

> "**NavLink** — **현재 URL과 일치하면** 스타일을 줄 수 있어요. 메뉴에서 **어느 탭이 선택됐는지** 표시할 때 좋아요. `className`에 함수로 **`isActive`** 를 받는 패턴이 슬라이드에 있어요."

**전환**

> "**프로그램으로 이동**하거나, **URL 안의 id**를 읽을 때 쓰는 Hook이에요."

## 슬라이드: 4.4 useNavigate, useParams

**멘트**

> "**useNavigate** — 예: 로그인 성공 후 **`navigate('/dashboard')`** 처럼 **코드로 이동**할 때 써요."

> "**useParams** — Route를 **`/user/:id`** 처럼 적어 두면, 컴포넌트에서 **`const { id } = useParams()`** 로 **문자열**로 읽어요. 숫자가 필요하면 **`Number(id)`** 같은 변환이 필요할 수 있어요."

**전환**

> "**5부, 폼 처리 및 검증**입니다. 2주차 제어 컴포넌트를 복습하면서 **검증**을 얹어요."

## 슬라이드: 오늘의 핵심 정리

**멘트**

> "슬라이드 다섯 줄 읽어 주며 보강할게요.  
> **useEffect** — 사이드 이펙트, **의존성 배열**이 핵심.  
> **useContext** — 전역에 가까운 공유, **남용 금지**.  
> **React Router** — URL과 화면 연결.  
> **폼** — 제어 컴포넌트 + 검증."

> "다섯 번째 줄 **커스텀 Hook**은 오늘 슬라이드에 깊게는 없었지만, **`use`로 시작하는 내 함수**를 만들어 로직을 묶는 거예요. 과제에서 **fetch 로직을 `useUser` 같은 이름으로 빼 보기**를 추천해요."

> "퀴즈 정리: **`[]`** 는 **마운트 시 effect 한 번**, 클린업은 **언마운트(및 재실행 전)** 에요."

**전환**

> "**과제** 슬라이드입니다."

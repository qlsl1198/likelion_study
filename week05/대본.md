## 1. 오프닝 (5분)

> “지난주 Todo API는 서버가 켜져 있는 동안만 데이터가 살아 있었죠. 서버를 끄면 메모리 데이터는 사라집니다. 오늘은 그 데이터를 DB에 저장합니다. 먼저 설치 부담이 적은 H2로 성공시키고, 후반에는 같은 코드로 PostgreSQL에 붙여 봅니다.”

칠판 또는 슬라이드에서 이 흐름을 먼저 보여준다.

```text
Postman
  ↓
Controller
  ↓
Service
  ↓
Repository
  ↓
H2 또는 PostgreSQL
```

강조할 점:

- Java 코드는 한 번 작성한다.
- H2와 PostgreSQL은 `spring.profiles.active` 값으로 바꾼다.
- H2 데이터가 PostgreSQL로 자동 이전되지는 않는다.

## 4. Entity 작성 (25분)

`Todo.java`를 작성한다.

설명은 길게 하지 말고 아래만 짚는다.

- `@Entity`: DB 테이블과 연결
- `@Table(name = "todos")`: 테이블 이름
- `@Id`: 기본키
- `@GeneratedValue`: id 자동 증가
- `protected Todo()`: JPA가 객체를 만들 때 필요

멘트:

> “이 클래스 하나가 DB의 todos 테이블과 연결됩니다. 필드는 대부분 컬럼이 됩니다.”

작성 후 서버를 재시작하고 H2 Console에서 `TODOS` 테이블 생성 여부를 확인한다.

## 5. Repository 작성 (15분)

`TodoRepository` 작성.

멘트:

## 6. Service 작성 (25분)

`TodoService` 작성.

강조할 점:

- Controller가 Repository를 바로 부르지 않고 Service를 거친다.
- DB를 바꾸는 메서드는 `@Transactional`을 붙인다.
- `toggleCompleted`에서는 객체 값을 바꾸면 트랜잭션 종료 시 JPA가 변경을 감지한다.

멘트:

> “지난주에는 메모리 List에 넣었고, 오늘은 Repository에 저장합니다. 흐름은 거의 같습니다.”

## 8. Postman으로 H2 검증 (20분)

순서:

1. `GET /api/todos` → `[]`
2. `POST /api/todos` → 201 Created
3. `GET /api/todos` → 목록 확인
4. 서버 종료
5. 서버 재실행
6. `GET /api/todos` → 데이터 유지 확인

멘트:

> “서버를 껐다 켰는데도 남아 있으면 H2 파일 DB 연결이 성공한 겁니다.”

여기서 반드시 잠깐 멈춘다.

- 데이터가 안 남는 학생은 `jdbc:h2:mem`을 쓰고 있지 않은지 확인
- H2 Console URL이 다르면 다른 DB를 보고 있을 수 있음
- Postman에서 생성한 id를 한 번 더 조회하게 한다

---

## 9. PostgreSQL 전환 (35분)

PostgreSQL 설치가 된 학생 기준으로 진행한다.

DB 생성:

```sql
CREATE DATABASE tododb;
```

`application-pg.properties`에서 비밀번호 수정 후:

```properties
spring.profiles.active=pg
```

멘트:

> “여기서 Java 코드는 안 바꿉니다. 저장소만 H2에서 PostgreSQL로 바꾸는 겁니다.”

자주 나는 에러:

- `Connection refused`: PostgreSQL 서버 꺼짐
- `password authentication failed`: 비밀번호 오타
- `database "tododb" does not exist`: DB 생성 안 함

---

## 10. PostgreSQL 상태에서 같은 API 재검증 (15분)

H2 때와 같은 요청을 다시 실행한다.

1. `GET /api/todos`
2. `POST /api/todos`
3. `GET /api/todos`
4. `PATCH /api/todos/{id}/toggle`
5. `GET /api/todos/search?completed=true`
6. `DELETE /api/todos/{id}`

설명:

> “H2에 있던 데이터가 PostgreSQL로 자동 복사되지는 않습니다. PostgreSQL은 새 저장소라서 새로 POST하면 됩니다.”

---

## 11. 마무리 (5분)

오늘의 핵심:

- `@Entity`는 테이블과 연결된다.
- `JpaRepository`는 기본 CRUD를 제공한다.
- H2는 빠른 실습용으로 좋다.
- PostgreSQL은 실제 서비스와 더 가깝다.
- Profile을 쓰면 같은 코드로 DB를 바꿀 수 있다.

과제 안내:

- H2 상태에서 동작 캡처
- H2 서버 재시작 후 데이터 유지 캡처
- PostgreSQL 상태에서 같은 API 동작 캡처
- 실제 DB 비밀번호 커밋 금지

마지막 확인 질문:

1. “H2와 PostgreSQL은 Java 코드가 달라졌나요, 설정이 달라졌나요?”
2. “H2 데이터가 PostgreSQL로 자동 이동하나요?”
3. “`JpaRepository`가 기본으로 제공하는 메서드 2개는?”
4. “Postman에서 201과 204는 각각 어떤 상황에서 봤나요?”
